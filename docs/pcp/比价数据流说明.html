PCP 比价流程 · 数据流说明

更新日期：2026-09-22 ｜ 适用范围：政策导入业务模式 ｜ 视角：数据怎么流动、属性怎么产生（不涉及代码实现）

总览：一条数据的旅程

核心记忆点：航线是锦绣请求的拆分单位；日期是携程请求的拆分单位； 套餐不是"拆"出来的——锦绣返回的航班项自带套餐数组，程序只给它补价格换算和底价。 「主行参与」开关默认关闭：主行只作套餐的公用信息来源，政策行由匹配到携程报价的套餐各生成一条。

阶段 0：上传 Excel → a1 航线清单 a1

上传文件的格式是一张表，前 3 行是全局设置，第 4 行起每行一条航线：

位置内容作用
第 1 行航司二字码（如 XQ）全局航司，应用到所有航线
第 2 行舱位串，逗号分隔（如 Y,T,W）全局舱位序列，决定后续要匹配哪些舱位
第 3 行表头（占位）不校验内容
第 4 行起每行一条航线：出发机场、到达机场每条航线生成一条 a1 记录 = 一个锦绣请求任务

产生的 a1：每条航线一行，携带「出发机场 / 到达机场 / 航司 / 舱位串」四样信息。 它是后面一切数据的"根"，锦绣请求的入参就来自它。

阶段 1：锦绣获取官网数据 → a2 日期×舱位条目 a2

请求：每个 a1 航线发 1 个锦绣请求，入参只有三个：出发机场、到达机场、航司。

响应：一份该航线下所有「航班 × 舱位 × 日期」的原始报价数组。 每条原始项自带这些字段：舱位、成人总票价（CNY）、出发时间、出发/到达机场、航班号、剩余座位数、货币种类、行李信息数组、套餐信息数组。

处理第 1 步——筛选：两道门槛，不满足直接淘汰：

门槛规则目的
座位数剩余座位数 ≥ 配置值（默认 3；有套餐时看套餐首个的座位数）滤掉没票可售的航班
出发日期必须 ≥ 3 天后政策要生效需要提前量

处理第 2 步——贪心选航班： 按用户舱位串的每个舱位各选一条航班，同时让所用出发日期数量最少——因为每个日期后面会拆成 1 个携程请求，日期越少越省携程限流额度。

处理第 3 步——给选中的舱位条目富化属性：

新增属性怎么得来
显示价成人总票价（CNY）向上取整到元，只在界面显示用
底价（我方底价）把成人总票价（CNY）代入用户配置的底价公式算出来，保留 2 位小数。 公式计算顺序：先看区间配置有没有命中 → 命中用区间公式；没命中用全局公式；公式为空/出错降级为原价。 公式里的变量 cost 就是成人总票价（CNY）。
底价公式命中标记记录这次底价是哪条规则算的（区间 [500,700] / 全局 / 降级原价）+ 公式文本 + 入参 cost，供底价检查文件展示"底价公式命中"列和界面调试
出发日期从出发时间截取日期部分（YYYY-MM-DD）
出发 / 到达城市优先取接口返回的 C出发城市 / D到达城市；接口缺失时才用机场三字码→城市码兜底转换
托运行李串数行李信息里"托运"条目：0 件 → 无免费托运行李；1 件 → 成人:20；N 件 → N件，每件20。 这串文字是携程比价时做行李匹配的关键依据
套餐富化（每个自带套餐）① 套餐价_CNY = 套餐价格按汇率（货币种类）换算成人民币； ② 套餐我方底价 = 底价公式（套餐价_CNY）； ③ 套餐同样挂公式命中标记。 套餐数据异常一律不报错，只在数据上补「套餐数据说明」属性说明情况（无套餐数据 / 套餐数组为空 / 套餐数据格式异常 / 含无效套餐项 / 套餐价格缺失 / 套餐价格无效）

处理第 4 步——按日期分组： 把同一航线下选中的全部舱位条目按出发日期分组：date_obj = { 日期1: [舱位条目…], 日期2: [舱位条目…] }。 这就是 a2 的核心结构——每个日期后面会拆成 1 个携程请求。

阶段 2：携程比价 → 给舱位条目补比价属性

请求：a2 里每个「航线 × 日期」组合发 1 个携程请求（同日期多舱位合并到一次请求里）。 入参：出发城市、到达城市、出发日期、航司名。

响应：两部分： ① 航班列表（航班号 / 出发机场 / 到达机场 / 起飞时间 / 航班ID）； ② 报价列表（挂在航班上）：每条报价携带 舱位、携程底价、行李、是否自有报价、平台外显状态等。

匹配规则（找同一条航班 与 命中的报价）——按当前规则，舱位已不参与判定：

步骤判定条件
① 航班身份航班号一致 + 出发机场一致 + 到达机场一致 + 出发日期一致（联程按航段号序列一致 + 首起/末降 + 首段日期）
② 报价关联携程报价通过挂接关系指向上面那条航班的航班ID
③ 命中报价非自有报价（我方自己投放的不算对手） + 行李匹配（只比托运，手提不参与）：双方都无托运 → 匹配；否则托运件数相同且单件重量相同
★ 携程价口径：一律向下取整（正常是整数；万一非整数如 19.9 → 19），后续排序、比价、生效价都基于取整后的价格
★ 单个套餐可能匹配到多条携程报价：先按价格从低到高排序，从最低价开始逐条比， 命中的是第一个「我方底价 ≤ 该价」的报价（能比过的价格里最低的那条）； 全部比不过 → 套餐标记「无可比过」并跳过（主行模式则 lost 贴我方底价卖）

主行参与开关（政策字段配置面板里，默认关闭）——决定"主行还是套餐"产出政策行：

开关状态行为
关闭（默认）主行只作为套餐的公用信息来源（机场/城市/航班号/时间等取值处），不参与比价； 仅匹配到携程报价的套餐各生成一条政策行：公用信息继承主行，舱位用套餐自己的（没有则用主行舱位）， 调价金额 = 该套餐差值（命中价 = 能比过的报价里价格最低的那条）； 未匹配或全部比不过的套餐跳过（套餐上留有「套餐数据说明」）
开启主行参与比价：多条匹配报价同样从低价到高价逐条比，命中能比过的最低报价（won）； 全部比不过 → lost（贴我方底价卖），主行产出政策行；套餐的比价结果只在底价检查文件里体现

比价判定与新增属性（对每条我方舱位条目）：

新增属性怎么得来
携程底价命中报价里携程返回的底价数值，原样记录
比价结果标记我方底价 > 0 且 ≤ 携程底价 → 可以胜出 won； 我方底价 > 携程底价 → 无法胜出 lost（不丢弃，改为"贴我方底价卖"）
调价金额 CUT_VALUE计算阶段只保留精确价差（不含 −1，可带小数）：won = 命中携程价(取整) − 显示价；lost = 我方底价 − 显示价（贴底价）。
写入政策文件/底价检查文件前统一「向下取整再 −1」（平台只接受整数）：整数价差 → −1，生效价恰 = 携程价(取整) − 1；小数价差 → floor(v)−1，生效价比携程价(取整) 低 1~2 元
是否自有（舱位级）命中报价的"是否自有"标记原样带上
套餐子项富化为每个套餐按行李匹配对应的携程报价（可能多条）：按价格从低到高逐条比， 套餐携程底价 = 能比过的报价里最低的那条价格；套餐差值 = 命中价(取整) − 套餐价_CNY（精确价差，不含 −1，写入文件前统一取整减1）；同步记录是否自有。 匹配失败或全部比不过的套餐不报错，只在套餐上加「套餐数据说明」（套餐无行李信息 / 未匹配到携程报价 / 无可比过的价格）
全部报价明细（界面展示用）把携程这次返回的每一条报价都列出来，逐一标注：比赢 won / 比输 lost / 自有外显 / 自有隐藏 / 未匹配（未匹配还会标出第一个不通过的参数：无此航班 / 行李不符 / 价格异常）。只用于界面，不参与比价和导出

阶段 3：政策行组装 → a3（147 列） a3

每条比价结果行（won + lost 都要）装成一条 147 列的政策行，列值来自三个渠道：

来源列值怎么来
① 政策字段配置（11 项，支持 ${变量}） Name、Remark、Y优先级、OTAConfigID、航程类型、数据有效期End、航司名、销售天数、座位数、爬虫名、创建人id 用户在"政策字段配置"页面填的模板文本，导出时把 ${变量} 替换成该行实际数据。 可用变量：出发机场、到达机场、出发城市、到达城市、航班号、航司名、舱位、仓等、出发时间、到达时间、成人总票价CNY、携程底价、预计减价
② 运行时对接字段 机场航线匹配、舱位、调价固定加减钱、UpdateTime 机场航线匹配 = 出发机场-到达机场 拼接；舱位 = 我方舱位； 调价固定加减钱 = CUT_VALUE（整数原样；有小数则去掉小数部分再 −1，如 −45.12 → −46）； UpdateTime = 行生成时刻（YYYY-MM-DD HH:mm:ss）
③ 固定值 是否启用=是、退改模式=不退不改、退票/退税/部分改期标识=未设置、各百分比与加减钱=0、价格基础类型=总价、团体资质=正常票、是否包机产品=否、同程resouceCategory=普通资源、nationality=TR 等 与"政导文件样例"的必填项取值对齐，写死
表格格式与样例文件完全对齐：147 列表头一致；数字列（Y优先级、OTAConfigID、数据有效期End、各百分比/加减钱、创建人id 等）保持数字类型，其余为文本；留空列写空字符串。ID / CreateTime 留空。

阶段 4：导出 Excel（点击下载产出的两个文件） xlsx

文件命名内容给谁用
政策导入文件 {平台名}导入政策{日期}.xlsx 147 列政策行，全部居中，won 行浅绿底 / lost 行浅红底 导入到平台系统执行调价
底价检查文件 {平台名}底价检查{日期}.xlsx 人看对照：每条舱位是"主行"，紧跟其下展开套餐子行。 主行列：航班号/舱位/机场/城市/时间/仓等/成人总票价/携程底价/预计减价/底价公式命中/行李额； 套餐子行只填：舱位/是否自有/成人总票价_CNY/携程底价/预计减价/公式命中/行李额 人工核对

底价检查文件里两个列的特殊算法：

列算法
预计减价与政策导入文件「调价固定加减钱」同值：写入前统一「向下取整再 −1」（计算阶段保留精确价差，平台只接受整数）；主行来源=CUT_VALUE，套餐行来源=套餐差值
底价公式命中文本化：「区间 [500,700] cost*0.48」/「全局 cost*0.2」/「降级 原价」
行李额只汇总托运重量（手提不展示）：「托运：20kg」；没有托运条目 →「托运：0」
调价口径：携程价一律向下取整（正常为整数，19.9 → 19）后参与比价； 计算阶段只保留精确价差（不含 −1），写入政策文件「调价固定加减钱」与底价检查文件「预计减价」前 统一「向下取整再 −1」（平台只接受整数）——整数价差时生效价恰 = 携程价(取整) − 1， 小数价差时生效价比携程价(取整) 低 1~2 元。 主行参与关闭时，底价检查文件的主行 = 套餐行（公用信息 + 套餐自己的舱位/价格/调价差值）。
