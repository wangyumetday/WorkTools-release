# PCP 携程比价：套餐对套餐展示 + 联程匹配改造

## Context（为什么改）

用户拿真实文件实测比价流水线后，发现日志里大量「未匹配」。诊断结论：

1. **展示层口径 bug（主因）**：主行参与关闭（默认）时，套餐级匹配成功不写 matchSink；`buildQuoteRows` 只能按「主行行李 + 胜负门槛」重判，把已命中的报价标成「行李不符」「价格异常」——假「未匹配」。
2. **联程不支持**：锦绣联程条目 `H航班号="XQ947,XQ7293"`（逗号拼接，接口原始值）；携程按航段存（flightRefs 挂多个 flightId）。业务匹配链 `flights_related` 只做单段四元组全等，联程套餐全部「未匹配到携程报价」。
3. 「匹配报价均低于我方底价」为规则内行为（不贴底价卖），无需改动。

用户确认的三个需求：

- 界面「对比过程与结果」改为**套餐对套餐**：我方锦绣套餐 ↔ 携程按行李额分的报价（prices[]）；主行参与开启时主行作为一个对比单元参与，关闭时不对比也不显示。
- 联程：**多程航段号全部匹配上才算匹配上**（业务匹配链同样支持联程）。
- 对不上任何套餐/主行的携程报价**保留为附加行**，标「无对应」。

## 设计要点

### 1. 新 quoteRows：我方驱动的「对比单元行」+「附加行」

| 字段 | 对比单元（kind=main/package） | 附加行（kind=other） |
|---|---|---|
| kind | main / package | other |
| flightNo/date/dep/arr | 我方组合航班号/日期/首起/末降 | 携程 journey 组合号/首起/末降 |
| seatClass / cabinClass / pkgIndex | acai.舱位（主行用 itemCangWei）、舱等、套餐索引 | seatClass |
| ourPrice / ourFloor | 套餐价格_CNY（主行为 totalCNY）、我方底价（主行为 dijia） | — |
| ourBaggageShort | 我方行李短文案（formatOurBaggageShort） | — |
| hitPrice / xcBaggage(原文+short) | 命中携程价+行李 | — |
| isOwn / shown / flagRemark / isInit | 来自命中报价（口径同现 L661） | 报价自身 |
| status | won / lost / unmatched | other |

- status 文案沿用现有映射：won=比赢、lost=比输、unmatched 按 reason（flight=无此航班、baggage=行李不符、price=价格异常）；新增 other=无对应。
- 行语义：won=套餐命中且可比过；lost=匹配到但全部低于我方底价（detail 用「匹配报价均低于我方底价，无可比过的价格」）；unmatched=未匹配到携程报价/套餐无行李信息（detail 直接用 acai['套餐数据说明']）。
- 附加行 = 未被任何对比单元「消费」的携程报价（无此航班 → reason=flight；有对应航班但行李对不上任何单元 → reason=baggage）。ownShown/ownHidden 仅出现在附加行的我方投放报价上。
- 消费规则：报价被某单元选中为命中价（含 lost 时曾进入候选）即算消费，不再出现在附加行。

### 2. summary 调整（mergeResult L799-808）

保留 flightCount/lowPriceCount；`quoteTotal/quoteOwn/quoteOwnShown/quoteOwnHidden` 改为**独立平铺枚举** resData 全部 prices[]（含 isOwn）计数（保住 TaskList 胜利率分母分子）；`quoteWon/quoteLost/quoteUnmatched` 改为新 quoteRows 口径；新增 `compareTotal/compareMain/comparePackage/otherCount`。

### 3. 联程业务匹配（priceComparisonPolicy）

- `splitCombinedFlightNo` 分隔符扩为 `/[-–—/，,]/`（加中英文逗号）。
- 新增 journey 预构建：把 lowPrices 按 flightRefs 还原成航段序列 `{nos[], dep, arr, date}`（复用 buildQuoteRows L626-648 的既有逻辑提为 helper）。
- 我方 `splitCombinedFlightNo(item.H航班号)` 与 journey 比对：**航段号序列全等** + 首起末降一致 + 首段日期一致 → 命中，其 prices[] 为 relatedPrices。直飞退化为现逻辑（结果不变）。
- `sortedValidPrices` 与「多报价命中取最低可比价」规则不变。

### 4. 套餐富化补写展示字段（L397-407）

命中分支补写：`acai._hitQuote`（报价引用）、`acai['携程行李原文']`、`acai.showState`、`acai.flagRemark`（口径同 L661）。未命中/lost 分支已有 `套餐数据说明`，展示直接复用。

## 边界与风险

- 旧任务数据不兼容：按项目约束直接改结构，删旧兜底。
- ExcelExporter 只吃 processedData，不碰；主行开启时套餐子行（读 acai 富化字段）不受影响。
- 联程跨日（多段日期不一致）：视为未匹配。
- 改造 flights_related 时保持直飞 processedData 字节级不变（重点回归）。
