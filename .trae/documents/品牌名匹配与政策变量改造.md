# PCP 套餐匹配新增「品牌名」条件 + 政策变量「品牌名」

## Context（为什么改）

锦绣返回数据里 `ExtValues.brandName_N`（N=套餐索引）是航司给每个套餐起的品牌名，携程报价条目带 `adtBrandNames[].brandName`。现在匹配只比航班/行李/中转，不够精确；两侧都有品牌名时必须一致才算匹配（忽略大小写+前缀包含，已确认），任一侧缺失则回退原有匹配规则。同时政策字段配置加「品牌名」变量供 Name/Remark 模板使用（取不到给 null）。只考虑成人（adt）。

## 数据格式（已从真实样本核实）

- 锦绣侧：`Content.List[].ExtValues.brandName_1/2/3`（string），数字后缀 = `套餐信息[].套餐索引`；无成人/儿童区分；ZE 等航司无此字段（=规则回退路径）；样本值 `SUNVALUE/SUNECOPLUS/SUNCOMFORT`。
- 携程侧：报价条目 `lowPrices[].prices[].adtBrandNames`（`[{segmentNo, sequenceNo, brandName}]`，只取成人字段；chd/inf 忽略）；样本值 `SunValue`、`SUNECO`。
- 缺失形态：null / 空串 / `"-1"`。

## 实施步骤

### 1. 锦绣侧富化 — electron/features/pcp/platforms/jxgj/adapter.js

- `enrichTaocanFloorPrice`（L162-192）循环体内（L176 之后）：
  `acai['品牌名'] = findItem?.ExtValues?.['brandName_' + acai['套餐索引']]`
- 缺失归一：值为 null/''/'-1' → 赋 null（或直接不写，视取值处容错）；其余 trim 保留原值。
- 注意 `findItem === rawItem`（原始 List 元素，ExtValues 在接口返回时原样保留），无需新增字段搬运。

### 2. 携程侧匹配过滤 — electron/features/pcp/platforms/trip/adapter.js

- `TRIP_RESPONSE_FIELDS` 新增 `adtBrandNames`（fieldNames.js L59-75 常量区）。
- 新增两个小 helper（priceComparisonPolicy 附近）：

```js
function quoteBrands(q) { // 报价携带的品牌名列表（成人；过滤 null/''/'-1'，归一 trim+大写）
  const arr = q?.[TRIP_RESPONSE_FIELDS.adtBrandNames]
  return Array.isArray(arr)
    ? arr.map(b => String(b?.brandName ?? '').trim().toUpperCase()).filter(v => v && v !== '-1')
    : []
}
function brandCompatible(ourBrand, qBrands) { // 忽略大小写 + 前缀包含（任一方以另一方开头）
  return qBrands.some(b => b === ourBrand || b.startsWith(ourBrand) || ourBrand.startsWith(b))
}
```

- `pkgCands` 计算（L463-467）之后插入过滤：

```js
const ourBrand = (() => { const v = acai['品牌名']; return v == null ? '' : String(v).trim().toUpperCase() })()
if (ourBrand && ourBrand !== '-1') {
  const brandQuotes = pkgCands.filter(q => quoteBrands(q).length > 0)
  if (brandQuotes.length > 0) pkgCands = brandQuotes.filter(q => brandCompatible(ourBrand, quoteBrands(q)))
}
```

- 语义：我方无品牌 或 候选中没有任何带品牌报价 → 规则不启用（老规则）；启用后只保留品牌兼容报价（带品牌但不兼容、或无品牌报价都排除——精确匹配）。命中/消耗/_matchedQuotes/原价判定自动follow 过滤后的 pkgCands。主行对比单元不启用品牌规则（品牌是套餐属性）。

### 3. 政策变量「品牌名」— fieldNames.js + policyFieldResolver.js

- `fieldNames.js` A3_FIELDS 增 `品牌名: '品牌名'`（参考「套餐索引」L53）。
- `policyFieldResolver.js` `POLICY_FIELD_VARS`（L23-38）增条目 `{ name: '品牌名', key: A3_FIELDS.品牌名, desc: '套餐品牌名（锦绣 ExtValues.brandName_N；获取不到为 null）' }`。
- `resolvePolicyField`（L56-68）特判：`v==null||v===''` 时，字段为品牌名 → 返回 `null`；其余字段维持 `''`（不改老行为）。
- 前端 PolicyFieldsConfig.vue 纯靠后端 `res.vars` 渲染，无需改；未获取到 null 时 Name/Remark 模板解析对该变量按 null 兜底（检查模板解析器对 null 的转字符串行为，若会变成 'null' 字符串需在解析器中留空处理）。

## 边界与风险

- 大小写归一 + 前缀包含是按样本（SUNVALUE↔SunValue、SUNECOPLUS↔SUNECO）定的口径，后续如有反例（前缀误配）再收紧为全等。
- 启用规则后无品牌报价被排除：仅在「同航班候选中混有带品牌报价」时发生；全无品牌（如 FA）自动回退老规则，不影响。
- 只动成人字段 adtBrandNames，chd/inf 忽略（符合"先只考虑成人"）。
