# PCP：中转航班判定、三字码匹配与航程类型自动化改造

## Context（为什么改）

1. 用户要求取消「政策字段配置」里的「航程类型」配置项，改为按数据自动判断。
2. 上轮实现的联程匹配（组合号拆段 vs 携程航段序列全等）在实测中仍有大量「未匹配到携程报价」；用户观察到锦绣的中转信息与携程中转报价的表达存在连接符差异等问题，要求匹配时「航班号 + 中转三字码都要匹配上」。
3. 实测数据事实（20260922_1326_XQ_1 run-log，AYT→LHR 中转航线）：
   - 锦绣中转条目：`H航班号="XQ152,XQ4162"`（逗号组合号）、分段信息两段（`XQ152 AYT→STR` + `XQ4162 STR→LHR`）、`S是否中转=true`、**`Z中转机场=null`（恒 null）**。
   - 携程中转报价：行李串 `"AYT-STR-LON:成人:20.0KG"`（前缀=出发-中转-到达三字码链）、seatClass 如 `"O-O"`、flights[] 按航段单号存放、lowPrices.flightRefs 挂多个 flightId。
   - 结论：`Z中转机场` 判中转不可行；可靠依据是**分段信息段数**与组合航班号；中转三字码取**段间机场**（首段到达=次段出发）。

## 决策口径（含用户已确认项）

- **中转判定**：`分段信息` ≥2 段（或组合航班号拆段 ≥2）即视为中转航班，`S是否中转=true` 为辅助佐证。
- **我方中转三字码**：`Z中转机场` 若为三字码则优先采用；否则取 `分段信息[0].ap`（首段到达）；规范化 = trim + 大写 + `/^[A-Z]{3}$/`。
- **匹配规则（中转条目）**：航段号序列逐段全等（**两端都经 splitCombinedFlightNo 归一，消除连接符差异**；携程侧 flatMap 防组合号坍缩进单条 flightNo）+ 中转三字码一致 + 首起末降一致 + 首段日期一致，**全部满足才算匹配**。
  - 携程中转码：航段数 ≥2 时取 `segments[0].arr`；航段坍缩（单 flightRef 组合号）时从报价 `baggage` 前缀 `/^([A-Z]{3})-([A-Z]{3})-([A-Z]{3,4}):/` 提取中间码逐报价兜底。
  - 直飞（单段、无中转码）保持现四元组逻辑不变（processedData 回归安全）；`Z中转机场=null` 的组合号条目继续走上轮「航段号全等」旅程匹配。
- **航程类型列**：中转 → `多程`，直飞 → `单程`（自动，不再读配置）。

## 实施步骤

### 1. electron/features/pcp/configManager.js

- 删除 `POLICY_FIELDS_SCHEMA` 中的 `{ key: '航程类型', label: '航程类型', default: '单程' },`（L35）。UI（PolicyFieldsConfig.vue 按 schema 循环渲染）自动消失；`loadPolicyFields` 按 schema 键过滤，旧 policyFields.json 残留键自动剔除，无需迁移。

### 2. electron/features/pcp/platforms/trip/adapter.js

- 新增 helper（放在 splitCombinedFlightNo 附近）：
  - `normalizeTransitCode(v)`：trim+大写+严格三字码，否则 null。
  - `extractTripTransitCode(baggage)`：从 `AYT-STR-LON:` 前缀取中间码，容忍到达位 3-4 字母（城市码 LON）。
- `priceComparisonPolicy` item 循环内（L370 前）：
  - `myTransitCode = normalizeTransitCode(item['Z中转机场']) ?? 分段信息[0].ap 规范化`
  - `isTransit = 分段信息≥2 段 || splitCombinedFlightNo(H航班号).length >= 2`
  - `tripType = isTransit ? '多程' : '单程'`，写 `item['航程类型'] = tripType`
- 匹配分支（L370-407）改为：
  - `isTransit || oursNos.length >= 2` → journey 匹配：
    - `flatNos = segs.flatMap(s => splitCombinedFlightNo(s.no))`（连接符归一）
    - 逐段全等 + 首起末降 + 首段日期（现状条件保留）
    - `myTransitCode` 非空时：segs.length≥2 取 `normalizeTransitCode(segs[0].arr)`，不等则跳过该 journey；segTransit 为 null（坍缩）时逐报价用 baggage 前缀兜底过滤
  - 否则 → 直飞四元组分支原样保留
- 主行关闭分支 entry 拷贝块（L415-435 一带）加 `entry['航程类型'] = item['航程类型']`（`{...acai}` 不含主行字段，必须显式拷贝）。
- exportTemplate L989：`{ key: '航程类型', ...pf('航程类型') }` → `{ key: '航程类型', from: (item) => item['航程类型'] ?? '单程' }`。

### 3. _local/tests/trip-compare-test.mjs（追加 5 组断言）

- T7 中转双命中：`H航班号='XQ152,XQ4162'` + 分段信息两段 + `Z中转机场=null`，携程两段单号 `XQ152 AYT→STR`/`XQ4162 STR→LHR`，baggage `AYT-STR-LON:成人:20KG` → package won 且 `processedData[0]['航程类型']==='多程'`。
- T8 连接符不一致：锦绣逗号组合号 vs 携程单条 `flightNo='XQ152-XQ4162'`（单 flightRef）→ won（flatMap 归一 + baggage 前缀兜底）。
- T9 三字码不一致：我方 STR、携程中转 IST → package unmatched（reason=flight），报价落 other 行。
- T10 组合号回归（Z中转机场=null 无分段信息路径）：`XQ947,XQ7293` 两段单号 → won（isTransit 走航段号全等，不校验三字码……注意：isTransit=true 但 myTransitCode 由分段信息取码，若无分段信息则无码，不额外校验）。
- T11 直飞：`XQ661` 单段 → won 且 `航程类型==='单程'`。

### 4. 验证

1. `node _local/tests/trip-compare-test.mjs` 全绿（19 旧 + 新断言）。
2. `npm run build` 三端构建通过。
3. 用户实测：AYT→LHR 中转航线重跑 → 组合号+段间码双匹配的套餐出政策行（航程类型=多程）；直飞仍是单程；对比表与日志口径不变。

## 边界与风险

- 直飞与无三段码的组合条目走原逻辑，processedData 回归安全（T10/T11 防护）。
- `Z中转机场` 字段不废弃：未来数据带三字码时自动优先用作中转码。
- 多中转点（如 A-B-C-D）暂不支持（单中转口径，`/^[A-Z]{3}$/` 单码）；出现时再扩展。
- ExcelExporter/底价检查文件无「航程类型」列，无需改动。
