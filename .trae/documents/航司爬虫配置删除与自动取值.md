# PCP 政策字段配置：删除「航司名」「爬虫名」配置，导出改为自动取数

## Context（为什么改）

锦绣政策字段配置面板里的「航司名」「爬虫名」两项是让用户手填的，但这两个值锦绣数据本身就有（航司名=每行 `H航司名`，如 XQ；爬虫名与航司同名，一个航司一个爬虫）。删掉两个配置项，导出列改为自动取锦绣数据，减少用户配置负担和填错可能。

## 实施步骤

### 1. configManager.js（electron/features/pcp/configManager.js）

- `POLICY_FIELDS_SCHEMA` 删除「航司名」（L34）与「爬虫名」（L37）两条。
- 旧配置键自动剔除机制已存在（`loadPolicyFields` L77-92 只保留 schema 内键），`policyFields.json` 里残留的旧值会自动丢弃，无需迁移代码。
- 前端 PolicyFieldsConfig.vue 纯 schema 驱动渲染，面板自动少两项，前端零改动。

### 2. adapter.js exportTemplate（electron/features/pcp/platforms/trip/adapter.js）

- 删除 L1176「航司名」的 `pf('航司名')` 配置版列，改为自动取值（沿用相邻列「航程类型」L1166 的 from 惯例）：

```js
{ key: '航司名', from: (item) => item[A3_FIELDS.H航司名] ?? '' }
```

- 删除 L1203「爬虫名」的 `pf('爬虫名')` 配置版列，改为同航司（已确认口径：爬虫名与航司同名）：

```js
{ key: '爬虫名', from: (item) => item[A3_FIELDS.H航司名] ?? '' }
```

- 字段可用性已核实：套餐政策行（buildPackagePolicyEntry L318 已拷贝 H航司名）与主行 item（L588/L598 push 原始 item）都有 `H航司名`。
- `pf()` 通用 helper（L1133）与 policyFieldResolver 的「航司名」变量（模板用 `${航司名}`）保留不动——变量与配置列是两条独立链路。

### 3. 测试 — _local/tests/trip-compare-test.mjs

- 增 T27：从 `exportTemplate.columns` 取「航司名」「爬虫名」两列，断言：
  1. `from` 为函数且不从 `ctx.policyFields` 取值（传 `{ policyFields: {} }` 也能返回 'XQ'）；
  2. 合成 item `{ H航班号:'XQ661', H航司名:'XQ', ... }` 时两列均返回 'XQ'；
  3. item 缺 H航司名时返回 ''（不报错）。

## 验证

1. `node _local/tests/trip-compare-test.mjs`（67+T27 全绿）、`node _local/tests/runlog-shard-test.mjs` 9/9。
2. `npm run build` 三端通过。
3. 界面确认：政策字段配置面板不再有「航司名/爬虫名」；导出 xlsx 两列值 = 锦绣数据 H航司名（如 XQ）。

## 边界与风险

- 旧持久化 policyFields.json 无迁移需求（per 项目约束：不考虑旧数据兼容）。
- policyFieldResolver 变量表「航司名」保留（`${航司名}` 模板变量照常可用）。
- 爬虫名列与航司列同源：未来若某航司爬虫名与航司码不同，需要再改为从锦绣数据源取或恢复配置。
